```

├── docs/                         # Comprehensive documentation of our system, detailing high level concepts and control flow
├── plans/                        # planned future systems for our system, detailing full implementation plans
```

## Module: vulkan-bindings
- Auto-generated by `generate-vulkan-bindings.bat` and `generate-vulkan-win32-bindings.bat` using jextract
- Package: `io.github.yetyman.vulkan.generated`
- Contains raw FFM bindings: `VulkanFFM.java`, all `Vk*` structs, constants
- Win32-specific types in `io.github.yetyman.vulkan.generated.win32`
- Not meant to be edited by hand

## Module: glfw-bindings
- Auto-generated by `generate-glfw-bindings.bat` using jextract
- Package: `io.github.yetyman.glfw.generated`
- Bundles native GLFW DLLs in `src/main/resources/natives/`
- Provides window creation, input, and Vulkan surface creation

## Module: shaderc-bindings
- Auto-generated FFM bindings for the shaderc GLSL-to-SPIR-V compiler
- Package: `io.github.yetyman.shaderc.generated` (FFM), `io.github.yetyman.shaderc.enums` (enums)
- Used by `ShaderLoader` for runtime GLSL compilation

## Module: spirv-reflect-bindings
- Auto-generated FFM bindings for SPIRV-Reflect
- Package: `io.github.yetyman.spirv.generated` (FFM), `io.github.yetyman.spirv.enums` (enums)
- Used by `ShaderLoader.ShaderReflection` for descriptor/push-constant/spec-constant introspection

## Module: stb-truetype-bindings
- Auto-generated FFM bindings for stb_truetype font rasterization library
- Package: `io.github.yetyman.stbtruetype.generated`
- Used by `FontRegistry` in vulkan-ffm-sample-ui-layers for glyph rasterization, metrics, and atlas packing
- Bundles native stb_truetype shared library in resources/natives/

## Module: helpers-core
- Pure Java utilities with zero dependencies
- Package: `io.github.yetyman.helpers`
- Available to all modules as a lightweight shared utility layer

## Module: vulkan-core
Package root: `io.github.yetyman.vulkan`

### Top-level wrappers (Vk*.java)
Each wraps a Vulkan handle with a Builder and AutoCloseable:
- `VkInstance`, `VkDevice`, `VkPhysicalDevice`, `VkQueue`, `VkCommandBuffer`, `VkCommandPool`
- `VkBuffer`, `VkImage`, `VkImageView`, `VkSampler`
- `VkRenderPass`, `VkFramebuffer`, `VkPipeline`, `VkShaderModule`
- `VkDescriptorPool`, `VkDescriptorSet`, `VkDescriptorSetLayout`
- `VkFence`, `VkSemaphore`, `VkSwapchain`, `VkSurface`
- `VkComputePipeline` — compute pipeline with specialization constants, push constants, dispatchAndWait
- `VkTimelineSemaphore` — timeline semaphore with CPU signal/await/counterValue
- `VkSparseImage` — sparse residency image with on-demand tile commit/decommit (virtual texturing)
- `VkResult` (enum), `VulkanException`, `Vulkan` (static API facade)
- `WindowSystem` — interface for windowing system integration (implemented by GLFWWindowSystem in sample-app)

### Top-level operation/utility wrappers
Stateless builder/utility classes for common Vulkan operations:
- `VkSubmit` — fluent submit builder (wait/signal semaphores, command buffers)
- `VkSubmitBuilder` — timeline-semaphore-aware submit builder (used by TransferBatch)
- `VkPresent` — fluent present builder
- `VkPushConstants` — type-safe push constant factory (floatValue, intValue, floatArray, Builder)
- `VkViewport` — viewport builder returning MemorySegment
- `VkRect2D` — scissor/rect builder returning MemorySegment
- `VkClearValue` — clear value factory (color, depthStencil)
- `VkClearValues` — multi-clear-value array builder
- `VkVertexBufferBinding` — vertex buffer bind helper
- `VkBufferCopy` — VkBufferCopy struct allocator
- `VkCommandBufferAlloc` — command buffer allocation builder
- `VkFenceOps` — fence wait/reset/status operations builder
- `VkPhysicalDeviceOps`, `VkSurfaceOps`, `VkSwapchainOps` — query helpers
- `VkQueueFamily` — queue family index finder
- `VkResizeHandler` — swapchain resize callback
- `VkFramebufferAttachment` — framebuffer attachment descriptor
- `VkMappedMemoryRange` — mapped memory range helper
- `BufferHandle` — thread-safe atomic VkBuffer handle wrapper
- `VkRendering` — dynamic rendering pass builder (Vulkan 1.3 / VK_KHR_dynamic_rendering); replaces VkRenderPass+VkFramebuffer

### Barrier wrappers
- `VkBarrier` — abstract base with execute(commandBuffer, srcStage, dstStage)
- `VkMemoryBarrier` — global memory barrier builder
- `VkBufferBarrier` — buffer memory barrier builder
- `VkImageBarrier` — image memory barrier builder (layout transitions)

### Sparse binding wrappers
- `VkSparseMemoryBind`, `VkSparseBufferMemoryBindInfo`, `VkBindSparseInfo` — sparse buffer binding struct builders
- `VkSparseImageMemoryBind`, `VkSparseImageMemoryBindInfo` — sparse image binding struct builders

### commands/
Moved out of highlevel — command pool and buffer management:
- `CommandManager` — manages command pools with optional per-thread pool support; Builder accepts `context(VulkanContext)` or `device`+`arena`
- `CommandPoolRegistry` — static thread-local per-device per-family command pool cache; `getOrCreate`, `destroyThread`, `destroyAll`
- `TransientCommandBuffer` — RAII one-shot command buffer with `begin`, `execute`, `submitAndWait`, `copyBuffer`, `copyBufferToImage`, `copyImageToBuffer`, `copyImage`, `transitionImageLayout`, `memoryBarrier`

### shaders/
Full shader compilation, reflection, code generation, and runtime binding system:
- `ShaderLoader` — static facade for GLSL→SPIR-V compilation via shaderc + SPIRV-Reflect reflection
  - `ShaderLoader.Builder` — fluent builder: source language, defines, inline source, optimize, compile/load
  - `ShaderLoader.ShaderReflection` — parsed reflection: descriptor sets, push constants, specialization constants
  - `ShaderLoader.DescriptorSetInfo`, `DescriptorBindingInfo`, `PushConstantBlockInfo`, `StructMemberInfo`, `SpecializationConstantInfo` — reflection data types
- `CompiledShader` — compiled SPIR-V + reflection + descriptor set layout generation
- `GeneratedDescriptorSetLayout` — VkDescriptorSetLayout built from reflection data; owned by ShaderInstance or DescriptorGroup (moved from `CompiledShader` inner class to top-level in `shaders/`)
- `ShaderInstance` — runtime instance: owns descriptor pool/sets, typed slot factories, flush()
  - Builder with specialization constant overrides and define-based variants
  - `buildSpecializationInfo(Arena)` for pipeline creation
- `ShaderGenerator` — generates typed Java wrapper classes from compiled shaders (CLI + API)
- `ShaderManager` — shader cache + module lifecycle + `ShaderSet` (vertex/fragment/geometry/compute/tess grouping); Builder accepts `context(VulkanContext)` or `device`
- `DescriptorGroup` — bundles layout + pool + set + buffer bindings in one shot; reflection-aware builder
- `DescriptorSlot` — abstract dirty-tracked descriptor binding base
- `StorageBufferSlot`, `UniformBufferSlot`, `TextureSlot` — typed descriptor slot subclasses
- `PushConstant<T>` — dirty-tracked push constant value holder
- `ShaderExample` — comprehensive integration test exercising all shader features

### buffers/
Advanced buffer strategy system:
- `AbstractBuffer` — base class with arena, device, usage, strategy fields
- `ManagedBuffer` — interface: handle(), size(), write/writeAsync/read/copyTo/flush/close
- `MappedBuffer` — persistent CPU-mapped (HOST_VISIBLE | HOST_COHERENT)
- `DeviceLocalBuffer` — GPU-only with staging transfers
- `MirroredObservability` — mirrored CPU observability with companion host-visible VkBuffer for CPU reads + staging source
- `MirrorCapable` — capability interface for observability implementations with a mirror buffer
- `CpuObservability` — strategy interface for how the CPU reads buffer contents (none, inherent, mirrored)
- `NoneObservability`, `InherentObservability` — non-mirrored observability implementations
- `DirtyStrategy` — interface tracking which byte ranges have changed since last flush
- `AlwaysDirtyStrategy`, `RangeCoalescingDirtyStrategy`, `BitSetDirtyStrategy` — dirty tracking implementations
- `ReBarBuffer` — Resizable BAR direct CPU→VRAM mapping
- `RingBuffer` — N-buffered ring wrapping another strategy
- `SparseBuffer` — sparse virtual memory with on-demand page binding
- `SuballocatorBuffer` — single large buffer with sub-allocations
- `SparsePageAllocator` — page lifecycle (bind/unbind/map/unmap) for SparseBuffer
- `BufferFactory` — creates ManagedBuffer by MemoryStrategy enum
- `BufferStrategySelector`, `BufferStrategyTable`, `BufferStrategySelection` — strategy selection
- `AccessFrequency`, `BufferUsage`, `DataScale`, `MemoryStrategy` — enums/strategy types
- `TransferCompletion` — async transfer handle with await/onComplete/close
- `BatchTransferCompletion` — shared ref-counted completion for batched transfers
- `TransferBatch` — batched command buffer recording with auto-flush threshold + timeline semaphore support
- `TransferBatchManager` — per-thread per-queue TransferBatch registry
- `BufferWritable` — interface for GPU-serializable types (byteSize, writeTo, readFrom)
- `BufferExample` — integration test

### buffers/typed/
Typed array views over ManagedBuffer:
- `TypedVkBuffer<T extends BufferWritable>` — abstract typed array: single/bulk read/write, optional CPU mirror, GPU copy
- `FloatVkBuffer` — float[] direct transfer, optional FloatBuffer mirror
- `IntVkBuffer`, `LongVkBuffer`, `ShortVkBuffer`, `DoubleVkBuffer` — primitive typed buffers

### graph/

### highlevel/
Application framework layer:
- `VulkanApplication` — base class for Vulkan apps; `Config` inner class (validationLayers, windowSystem, inputSystem, logger, resizable); lifecycle: `run()` → initWindow/initVulkan/initInput/initialize/mainLoop/cleanup; abstract: `initialize`, `render`, `onResize`, `shutdown`; optional: `configureInput`, `onFPSUpdate`
- `VulkanContext` — aggregates instance, device, queues; Builder auto-detects dynamic rendering support and enables it; `createGraphicsCommandPool`, `createTransientCommandPool`, `createDescriptorPool`, `createVertexBuffer`, `createStagingBuffer`, `createUniformBuffer`
- `GraphicsRenderer` — abstract renderer replacing `BaseRenderer`; constructors accept `useDynamicRendering` and `sampleCount`; `init(queueFamilyIndex)` creates all resources; abstract: `recordCommandBuffer`; optional hooks: `createRenderPassImpl`, `createFramebufferImpl`, `initializeResources`, `postRenderPassInit`, `onResize`, `cleanupResources`
- `GraphicsLoop` — composes `GraphicsRenderer` with `LoopThread`; handles frame gating, resize coordination, idle sleeping, FPS tracking; `signalResize(w,h)` is thread-safe; Builder: `renderer`, `driver`, `timing`, `shouldClose`, `shouldRender`, `pollEvents`, `onResize`, `onFpsUpdate`, `idleSleepMs`; `runOnCurrentThread()` or `start()` for dedicated thread
- `SwapchainManager` — swapchain + image views + per-image semaphores; `SwapchainImage` record (image, imageView, imageAvailableSemaphore, renderFinishedSemaphore); `recreate(w,h)`; Builder accepts `context(VulkanContext)` or `device`+`arena`
- `VulkanCapabilities` — device feature/extension queries; `dynamicRendering` static field set by `initialize(physicalDevice)`
- `VkResourcePool`, `VkSizedResourcePool` — generic resource pooling
- `DrawCommand` — draw abstraction (direct, indexed)
- `RenderList` — declarative multi-pass render graph (graphics/compute/generic passes, conditional, parallel)
- `PoolAllocator`
- `VkTexture`, `VulkanMesh`, `VkVertexFormat`, `VulkanRenderTarget`

### loop/
Decoupled loop infrastructure (new package):
- `LoopDriver` — interface controlling rate/timing of loop execution; static factories: `uncapped()`, `fixedRate(hz)`, `fixedRateCatchUp(hz)`, `vsync(VsyncSource)`; inner interfaces: `VsyncSource`, `BooleanSupplier`
- `LoopThread` — managed thread driving a `Consumer<TimingStrategy>` work function; `start()`, `stop()`, `runOnCurrentThread()`, `driver(LoopDriver)` (hot-swap); Builder: `driver`, `timing`, `work`, `name`
- `TimingStrategy` — interface for frame/section timing; static factories: `none()`, `profiled()`, `budgeted(Map)`; `lastFrameNanos()`, `lastSectionNanos(section)`; inner class `Profiled` with budget-exceeded warnings

### sync/
Moved out of highlevel — synchronization primitives:
- `SyncManager` — unified sync facade: timeline semaphores by name, binary semaphores, fence pool, barrier factories, `createFrameSync(framesInFlight)`; inner classes `FrameSync` and `FrameSyncState`
- `SemaphoreManager` — manages named timeline semaphores and binary semaphores
- `FencePool` — pooled VkFence lifecycle

## Architectural Patterns
- **Layered abstraction**: generated bindings → core wrappers → high-level framework → sample apps
- **Module separation for major subsystems**: graph, node trees, and sample layers are separate modules with well-defined dependency edges
- **Builder pattern**: all major Vulkan objects use static `builder()` → fluent setters → `build(Arena)`
- **AutoCloseable**: all handle wrappers implement AutoCloseable for try-with-resources
- **Arena-scoped allocation**: all native memory allocated through `Arena` passed into builders
- **Static facade**: `Vulkan` class provides static methods wrapping `VulkanFFM` calls, always returning `VkResult`
- **Null allocator convention**: all Vulkan create/destroy calls pass `MemorySegment.NULL` for the allocator parameter
- **Dynamic rendering first**: `VulkanContext.Builder` auto-detects and enables dynamic rendering; `GraphicsRenderer` uses it by default when `VulkanCapabilities.dynamicRendering` is true
- **Decoupled loop**: `LoopDriver` + `LoopThread` + `TimingStrategy` in `loop/` package; `GraphicsLoop` composes these with `GraphicsRenderer`
- **Reflection-driven shader binding**: ShaderLoader reflects SPIR-V → CompiledShader → ShaderInstance with typed slots
- **Transfer batching**: per-thread TransferBatch accumulates GPU copies, auto-flushes at 64MB threshold
- **Thread-local registries**: `CommandPoolRegistry` and `TransferBatchManager` provide per-thread resource caching
- **Node tree composition**: hierarchical component system with DI, typed events, traversal views, and UILayer composition
- **UILayer capture/bubble input**: two-phase input dispatch across layer stack with cross-layer context annotation

## Module: vulkan-ffm-node-trees
Node tree + UILayer composition system.
Package root: `io.github.yetyman.vulkan.nodetree` (tree/component system) and `io.github.yetyman.vulkan.ui` (layer/input system)

### nodetree/
Hierarchical composition system with DI, events, traversal views:
- `Tree` — root container, view registry, claim registry, tree components
- `Node` — tree node with components, children, typed event handlers, zero-alloc fireEvent
- `Component` — interface for attachable behaviors with full lifecycle
- `TreeComponent` — interface for tree-scoped singletons
- `TraversalView<C>` — incrementally-maintained ordered linked list, O(1) ops, dirty tracking
- `CaptureBubbleTraversal` — walks a view forward/backward for capture/bubble, zero alloc
- `TreeLayer` — optional UILayer bridge (owns a tree)
- `Event` / `EventType` / `EventHandler` — typed event system with identity-token types
- `PropertyNotifier<E>` — enum-keyed per-instance property change notification
- `Dependency` / `ClaimStyle` / `LookupScope` / `FallbackPolicy` — DI system
- `NodeQuery` — convenience query utility
- `BulkPropertyObserver` — bulk property observation

### ui/
UILayer composition and input dispatch:
- `UILayer` — self-contained rendering/input subsystem interface
- `UIComposite` — layer orchestrator (sort by order, initialize, update, render, dispatch, resize, close)
- `UIContext` + Builder — shared platform context (VulkanContext, AssetRegistry, dimensions, DPI)
- `UIFrameContext` — per-frame transient state (frameArena, deltaTime, frameNumber)

### ui/input/
- `InputEvent` — input event with type, phase, propagation state, payload
- `InputPhase` — CAPTURE / BUBBLE
- `InputEventType` — key, mouse, scroll, gamepad, touch, focus, window, drop
- `PropagationState` — stop/context/handled tracking across phases
- `UIInputDispatcher` — capture/bubble dispatch across layers
- `InputDispatchStrategy` — dispatch strategy interface
- `LayerProvider` — layer list provider interface
- `types/` — typed event data records (KeyInputData, PointerInputData, ScrollInputData, etc.)

### ui/assets/
- `AssetRegistry` — pure service locator (typed, does NOT own lifecycle of registered services)
- `AssetType` — type-safe key for registry lookups (class + optional name)
- `ClipboardAccess` — interface (platform impls elsewhere)
- `CursorManager` — interface (platform impls elsewhere)
